# 未知图腾笔记、字形记录与原生领奖路径核验

核验日期：2026-10-16。只读分析用户授权目录的3份精确ROM、mGBA即时存档和普通存档；没有改动ROM、存档或模拟器。下列内存写入验证全部发生在隔离Unicorn RAM副本。

## 结论与编辑边界

本改版的重要道具是 **740 / 0x2E4「未知图腾笔记」**，道具表的使用函数进入专用笔记菜单。746 / 0x2EA的实际ROM名称是「宝可梦图鉴」，不据此将它当成未知图腾专用图鉴。

28种字形记录是独立捕获旗标，不是全国图鉴的见过/捕获位，也不是按捕获顺序保存的数组。原生捕获指令按物种201、PID字形调用FlagSet。编辑这些记录不会生成宝可梦或改变全国图鉴。

界面开放28种捕获记录的手动编辑；AE0～AE5六个研究/体验记录只随明确警告并确认后的「补齐任务领奖条件」快捷草稿提交，不提供六项手动编辑控件。最终页与任务034完成共用1752，保留只读；不设置1751接取、不添加笔记道具、不改谜题、奖励、钱或点数。快捷草稿仅在已接取且未完成时生成34项记录为真的草稿，仍须预览和提交，然后在游戏中与研究员对话，由游戏发放奖励并置完成旗标。

## RAM、掩码和持久位置

扩展Flag范围900～18FF的地址是 `0203B174 + (flag - 900) // 8`，位序为`flag & 7`，与旧SaveBlock1+EE0旗标区域分开。

| 记录 | 旗标 | RAM / 位 | 允许补丁 | 存档映射 |
| --- | --- | --- | --- | --- |
| A～Z、!、? | 16EA～1705 | `0203B331..0203B334`，起bit2 | 4字节；字节掩码`FC FF FF 3F` | section4+E89，4字节 |
| 石板与电波汇报 | AE0 | `0203B1B0` bit0 | 与其余研究记录共1字节，掩码3F | section0+F60 |
| 电波体验 | AE1 | 同上 bit1 | 同上 | 同上 |
| 未知图腾语言汇报 | AE2 | 同上 bit2 | 同上 | 同上 |
| 排列文字汇报 | AE3 | 同上 bit3 | 同上 | 同上 |
| 秘密房间体验 | AE4 | 同上 bit4 | 同上 | 同上 |
| 最后两个符号汇报 | AE5 | 同上 bit5 | 同上 | 同上 |
| 已接取 / 已完成 | 1751 / 1752 | `0203B33E` bit1 / bit2 | 只读，参与守卫 | section4+E96 |

实际序列化函数将`0203B174`起CC字节复制到section0+F24，将`0203B240`起258字节复制到section4+D98。三版均用不同字节模式实际执行原函数，输出完整尾区一致。补丁保留字形记录首字节低2位、末字节高2位和研究字节高2位，也保留1751/1752及所有其他任务旗标。

原生计数函数循环16EA～1706，**含相邻1706共29位**。28种字形实际只写到1705。工具以8组隔离测试确认这个差异；编辑器计数仅统计28字形，不把1706当第29种字形或擅自清零。

## 任务034原生领奖路径

三版`08EC83C6..08EC8642`脚本逐字节相同，入口`08EC8125`先检查1751。仅把28捕获和4项汇报设真仍可能被AE1/AE4挡住。实际检查顺序是：

1. 1751已接取，否则转正常接取脚本。
2. AE0已汇报石板；AE1已有电波体验；AE2已汇报语言。
3. 16EA～1703共26个字母捕获齐全。
4. AE3已汇报排列；AE4已有秘密房间体验；AE5已汇报符号。
5. 1752尚未完成，1704和1705两种符号捕获齐全。
6. 到达原生奖励链`08EC85B5`：秘密琥珀162、贝壳化石165、甲壳化石166各1；`08EC8621`以原生`addvar 5135,15`加15 BracerPoints；随后原生addmoney增加15000。`08EC861E`在奖励链中设置1752。

NPC没有在这条已接取分支中单独检查关键道具740或三个拼图的完成位；这不证明世界上所有相关事件都只依赖上述记录。快捷草稿不替玩家接任务、添加关键道具或改谜题。

`trace_reward_branch`对真实ROM脚本进行有界控制流解释，跳过文本/声音标准调用，**在发道具指令之前停止**。每版37例：全部35个必要旗标满足时进入奖励链；逐一缺任一必要旗标的35例均不能进入；1752已完成也不能进入。这是ROM脚本分支证据，未模拟实际道具容量、上限、奖励动画或实机发放成功。

不能直接设1752来满足用户「完成并得奖」的目标：会跳过原生奖励分支。清除1752则可能重新开放已领取奖励，因此没有提供完成状态重置。六项研究记录仍会改变研究员对话/任务阶段，界面应列出具体旧值和新值；「全捕获」不能顺带设置研究记录。

## API与事务接入

2026-10-16最新界面约束：6项遗迹研究记录不生成分组或编辑控件，仅保留28字形与最终状态只读项。快捷按钮每次先弹出风险警告和完整 `.sav` 备份提醒；确认后六项作为待预览草稿，在预览及最终确认中逐项列明。取消不改变现有草稿或预览；普通字形全选不会携带研究记录。底层34项可写字段是受限事务接口，不代表界面开放六项单独编辑。

- `read_unown_records(memory, rom_sha256)`：重复读取捕获、研究、状态字节和两存档块指针，变化则拒绝。返回35个统一`fields`（34可编辑+最终页只读）、`task_accepted/task_complete`、原始`records`、4项`guards`。
- `prepare_unown_records_patches(snapshot, changes)`：只接受已核验字段的严格bool，最多返回捕获4字节和研究1字节两份`FieldPatch`，不写内存。
- `completion_changes(snapshot)`：已接取且未完成时返回34项真值草稿，否则明确拒绝；不会修改1751/1752或任何奖励。
- `unown_rom_features(sha)`：8项额外ROM字节守卫、合计866字节，包含完整领奖正文；须与外层真实ROM身份和兼容manifest检查合用，并在快照读取与同回调提交两处比较。

外层仍须写前备份、ROM检查、所有旧值/守卫比较、同回调读回，以及仅当前值仍等于已写值时的条件恢复。不能在后台线程操作Tk。

## 实际验证结果与限制

`python -m unittest tests.test_unown_records -v`：11项通过，含逐字形独立编辑、邻位保留、严格类型、未知字段/最终页拒绝、并发读取变化、坏指针、快捷草稿前提，以及三版完整领奖正文均纳入运行守卫、全文长度/原核验hash/边界与奖励命令覆盖。

`tools/verify_unown_records.py`：三版分别通过35项原生FlagGet、68项FlagSet/Clear对照、56项实际捕获指令片段、8项计数、2项完整尾区序列化、320项页面分支、37项NPC脚本分支。报告在已忽略的`diagnostics/unown-records-matrix.json`。

完整领奖正文运行守卫追加后，`tests.test_unown_transactions`的15项事务测试全部通过、无跳过。三版「全部34字段」的实际双记录提交均测得守卫加修改合计**64项、4080字节**，满足桥接上限≤64项、≤4096字节，项数已到上限；继续增加守卫前须重新审查预算。三版真实Lua/TCP回归均覆盖快照前、预览后、送入batch前修改正文尾字节，并验证全部零写；Memory夹具还覆盖精确ROM及兼容ROM。

1.0/1.2即时存档使用各自样本；1.33没有独立即时存档，使用1.2 RAM作为隔离夹具。三版普通存档与这些旧即时存档的完整扩展尾区都不一致，未据此声称配对存档一致或保存重载通过。当前证据覆盖ROM算法/布局和原生领奖路径可达性；实机笔记菜单、NPC实际领奖、游戏内保存重载仍待验收。
