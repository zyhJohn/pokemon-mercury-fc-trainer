## 0.2.10时间与每日日期交付

新增独立“时间 / 星期”页，显示正在运行的RTC日历、星期、AM/PM对调及错误提示、累计游玩时长、引擎每日刷新日期；同时可选择匹配本版ROM与`.sav`，离线读取RTC尾部日期、按当前电脑时区推算的时间和偏移、持久存档累计时长。目标日期自动预览星期，星期选择改变同一周的日期；校准先填预览，实际写入时以电脑当前时间为准、偏移归零。日历年份限定2000～2099，RTC写入保留每日事件记录。

mGBA 0.10.5会刷新游戏时钟缓存，硬件日期写指令没有实现，脚本API也没有适用的持久RTC设置入口。改用已核实的`.sav`末尾16字节：7个BCD字段、24小时控制字节、64位时间基准。关闭该游戏后才能独占写入，仅改尾部，128 KiB游戏数据与校验原样保留；整份旧存档和JSON记录先落盘/fsync，逐字节读回，条件恢复要求整份文件仍等于写入结果。旧即时存档、模拟器自定义RTC覆盖及跨电脑时区变化不在此文件偏移方案的自动处理范围。

累计时长使用SaveBlock2+0xE的小时u16及+0x10/+0x11的分秒，范围999:59:59。原版+0x12在本版存在0xFF等待标志并随帧变化，因此只改前4字节，保留帧计数。应用绝对填写值前读取当前时长备份，仍在回调中比较旧值；新增`BATCHVERIFY`能力，在同次Lua回调内完成读回，避免下一帧正常计时被误判为失败。原来的小事务、排序及CRC保护保持兼容；时间写入要求重载0.2.10脚本。

用户反馈先从10月1日跳到10月4日，随后10月2/3日仍显示周日内容，并已在改后保存。只读样本的引擎每日刷新记录确在未来日期；实际ROM的未来判断、每日允许/更新函数与持久section4位置吻合。提供“读取→预览→写入每日日期修复”，仅将Var5009/500A的4字节记录前移到当前游戏日期的前一天，让引擎重新执行当天刷新；不批量重置其他领取标志。日期/记录/RTC状态变化与战斗均拒绝，备份和条件恢复沿用内存事务。写入后用户在游戏内保存并重新进入地图或重开游戏；具体周日内容恢复仍待实机验收，不能保证所有自定义周常由这一条记录控制。

`tools/verify_time.py`完成26组实际ROM日历/星期/AM-PM转换、4组时长进位/上限、3组未来/今天/昨天的每日判定及实际日期记录序列化。最新`.sav`的每日记录和邻近字节与即时存档相符；RTC和累计时长样本分别只读分析，不默认整份两个文件同刻配对。自动化覆盖有效日期/闰日/跨周、星期选择、零偏移校准、文件占用、旧值变化、完整备份、部分写入、条件恢复、界面草稿保护及实际Lua/TCP写入；已有运行中的原存档通过独占拒绝检查，未改写用户原文件或运行内存。新功能的游戏菜单/实际每日刷新及保存重载仍需用户验收。

## 最重要的结论

- 队伍是固定 GAEM 顺序的明文 100 字节；旧文档的 PID 排列和 XOR 假设不适用本 ROM。校验相关代码已被关闭，保留原头部字节。
- PID 不是整只宝可梦的编码。闪光取决于 PID 与原训练师 ID 的异或值；IV/EV 独立存储。不要为“合法化”伪造一个全数据 ID。
- IV 字段高两位为蛋与隐藏特性标志，编辑必须保留。普通特性还依赖 PID 奇偶。
- PC 是 58 字节压缩记录，25 个盒子地址并非全部连续；不能按原版 80 字节直接写入。
- 经验必须使用 ROM 中提取的整数表。1 级门槛为 1；通用公式还在其他等级存在差异。
- “检查通过”仅代表当前结构与数值规则通过。已加入等级学习表与 TM/HM 兼容性证据，但没有完整遭遇、遗传、教学、进化前、配信或官方交换合法化。

具体地址、函数与来源见 [已验证布局](verified-layout.md)。旧版说明归档到 `逆向后记/README-旧版实现.md`，历史文档已加过时提示。

## 可靠性措施

Lua v3 只监听本机。连接及写入检查所选ROM的完整CRC32（V1.0：B4AF11C8；V1.2：4755F497）与各版49处代码特征；盒内写入额外检查压缩格式特征。每次事务在模拟器回调内先比较全部旧字节，再写入。队伍数量、SaveBlock 指针和战斗状态变化都会拒绝对应操作。玩家资料事务增加 SaveBlock2 指针比较，并在战斗中禁止写入。

写入前原始数据落盘并刷新，完成后逐字节读回。恢复也是条件事务，当前内容必须仍等于对应修改的结果；失败或结果未确认的记录不能自动恢复。关闭窗口会等待正在进行的操作和备份记录结束。旧 v1/v2 桥接只读。
