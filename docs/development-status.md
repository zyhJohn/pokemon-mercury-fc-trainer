## 最重要的结论

- 队伍是固定 GAEM 顺序的明文 100 字节；旧文档的 PID 排列和 XOR 假设不适用本 ROM。校验相关代码已被关闭，保留原头部字节。
- PID 不是整只宝可梦的编码。闪光取决于 PID 与原训练师 ID 的异或值；IV/EV 独立存储。不要为“合法化”伪造一个全数据 ID。
- IV 字段高两位为蛋与隐藏特性标志，编辑必须保留。普通特性还依赖 PID 奇偶。
- PC 是 58 字节压缩记录，25 个盒子地址并非全部连续；不能按原版 80 字节直接写入。
- 经验必须使用 ROM 中提取的整数表。1 级门槛为 1；通用公式还在其他等级存在差异。
- “检查通过”仅代表当前结构与数值规则通过。已加入等级学习表与 TM/HM 兼容性证据，但没有完整遭遇、遗传、教学、进化前、配信或官方交换合法化。

具体地址、函数与来源见 [已验证布局](verified-layout.md)。旧版说明归档到 `逆向后记/README-旧版实现.md`，历史文档已加过时提示。

## 可靠性措施

Lua v3 只监听本机。连接及写入检查加载 ROM 的 CRC32（B4AF11C8）与 34 处代码特征；盒内写入额外检查压缩格式特征。每次事务在模拟器回调内先比较全部旧字节，再写入。队伍数量、SaveBlock 指针和战斗状态变化都会拒绝对应操作。玩家资料事务增加 SaveBlock2 指针比较，并在战斗中禁止写入。

写入前原始数据落盘并刷新，完成后逐字节读回。恢复也是条件事务，当前内容必须仍等于对应修改的结果；失败或结果未确认的记录不能自动恢复。关闭窗口会等待正在进行的操作和备份记录结束。旧 v1/v2 桥接只读。
