用户已确认“引用暂存”：暂存只保存来源盒号/槽号、ROM身份和读取时完整记录的引用，原槽保留；加入或移除暂存引用不会写入游戏。正式开发时每次使用都重新比较原槽；槽位内容已变则引用失效，不能仅凭物种、昵称或PID认为是原个体。

## 新增盒子要求与验收门槛

神秘礼物投放约定：入口独立于单只编辑；队伍不满自动使用空位，满时显示六只成员供用户明确自选顶替，不设默认替换槽；盒子仅选1～25中的可用空槽，锁盒/满盒拒绝。模板来源、全部新个体字段和被顶替旧成员展示于预览；生成草稿后仍须统一检查提交。替换旧成员不自动转移到其他盒子，写前保存完整原记录用于条件恢复，未提交时可撤销草稿。正式上线依赖ROM初始化/PC编码、队伍数量守卫、所有目标旧值比较、读回及成功/中断/恢复/保存重载验收。原型示例不证明这些机制已完成。

1. 引用暂存及选择：左右两侧Shift＋左键逐只追加/取消，不做整段范围选中，不默认全选；相同来源引用去重。跨盒选择保留清晰计数，刷新、重连或源槽改变使相关引用失效。右键命中已选对象保留多选，命中未选对象切换至该对象。键盘提供同等操作。
2. 右键编辑：单只打开复用队伍右侧字段的独立弹窗。多只选择时禁用单只编辑，不任意选择其中一只；批量操作与单只编辑分开。草稿绑定原盒/槽及连接代次，旧异步结果拒绝覆盖新对象。
3. 任意数量快速移动：选择数量不人为限制；目标容量不足、任何来源失效或盒锁冲突时整次计划拒绝。正式事务需要重新设计批次日志、各批确认、停止与重连诊断；不能把任意数量包装为当前两槽接口循环后声称整批原子。超过单次桥接上限的总操作须展示已完成/未完成/未确认范围，记录恢复顺序；不会在断线后盲目重试或自动复制。
4. 快速生蛋/孵化：分开“将已有个体转为蛋”“培育屋产生待领取蛋”“缩短现有蛋的孵化等待”。周期归零不冒充计步器或完整孵化；确认本版引擎的零值语义、领取、孵化、PC取出和保存重载后再开放批量入口。
5. 盒子改名：核实本版25盒名称位置、字符编码、字节容量及终止符，验证中文/中英混合/满长/未知字符。UI实时显示字节占用；超长、不能显示或含不支持字符拒绝，不静默截断。原型只展示非空草稿，不采用宝可梦昵称或玩家名容量作为盒名规则。
6. 盒内按编号排序：正式默认内部物种/形态编号，明确区别全国图鉴号；稳定排序，同号保留原顺序，空槽末尾。完整58字节随个体移动，不改PID、招式、数量或OT。未知占用/空槽残留先核对后拒绝不确定重排；整盒旧值比较、读回与恢复，重复个体不可丢失。
7. 修改器内锁定盒子：锁定只是本地偏好，不改变ROM或游戏旗标；读取/查看/引用暂存允许，改名、排序、单只编辑、批量转蛋/孵化、移出及移入均拒绝。暂存引用、快捷键和后端写入再次检查不能绕过；恢复涉及锁盒时先明确解锁，不能自动跳过部分槽。持久化须按ROM及游戏实例关联，避免换ROM或换存档沿用错误盒锁。游戏自身仍能改变锁盒，旧值比较继续有效。

## 恢复机制核查结论

现有确认成功的修改可条件恢复，但不是任意故障下的全局自动回滚。内存事务备份保存本次修改处的before/after，不能代替完整`.sav`备份或撤销游戏在其他区域产生的进度。正式恢复默认拒绝覆盖后续变化。

| 场景 | 当前实现与验证 |
| --- | --- |
| 写前备份不能建立 | 持久JSON通过临时文件、flush/fsync和替换保存，备份失败不发送写入。Core/RTC测试已有覆盖。 |
| ROM切换、源或目标已变化 | 完整CRC及特征、指针/队伍数量/战斗状态、全部预期字节在Lua回调先比较后写入。过期第二槽不写第一槽；两版跨版恢复拒绝。 |
| 正常完成的单只跨盒移动 | 源清空及目标完整58字节在同一回调提交；写后读回，两槽备份。只有两槽均仍等于after时一起恢复；恢复本身再生成备份。 |
| 写入中抛异常、断线或写后值已被改变 | 标记failed-or-unconfirmed，保留两槽原字节，不自动重试或猜测逆写。Lua逐字节write8仍可能部分完成；同一回调不等于崩溃时事务自动撤销。当前UI拒绝未确认记录自动恢复，需要诊断和独立备份核对。新增两项故障注入明确验证这一边界。 |
| RTC文件写入 | 独占文件、整文件旧值比较、完整.sav备份和事务JSON、尾部写后整文件读回。部分写入保留全存档备份，未确认记录拒绝自动恢复；成功记录只有整份文件SHA仍匹配时恢复。 |
| 全局未锁盒排序、盒锁 | 0.2.13已接入：完整盒记录统一比較、同回调写入/读回、最多25整盒条件恢复；锁盒在写入/恢复后端拒绝。错误期间可能部分写入，未确认备份拒绝盲目恢复。 |
| 多批任意数量移动、新盒名 | 尚未实现；实现前仍须补总操作日志、限制预检、逐批状态、断线重连核对和安全恢复测试。 |

当前普通事务仍64项/8192字节/40000字符，简单源/目标逐槽方式仅余4只容量。0.2.13新增整盒专用BOXBATCHCRC：96项/65536字节/270000字符，仅完整1740字节盒记录写入，所有参与盒旧值统一比较、同回调读回；支持最多25整盒备份条件恢复。全局排序已使用该通道；任意数量批量移动仍未实现，不能据此标完成。

实机待验收：V1.2原存档迁移、各字段游戏显示、成功写入后的游戏内保存与重开、PC取出、完整孵化、实际断线及恢复。用户之前确认的成功写入不扩展成以上全部已完成。
