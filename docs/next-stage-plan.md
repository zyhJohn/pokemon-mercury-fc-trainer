# 下一阶段开发路线

更新：2026-10-02。来源：用户最新需求。本文件记录待实施工作，不代表新功能已经开放。

本轮状态：玩家ID与中文/中英混合姓名、队伍及PC详情、134个中文相遇地点及无效编号保护、队伍及PC蛋标志、队伍及PC未知图腾字形/晃晃斑花纹/小陨星核心颜色、ROM微缩图及左图右数值格子选择已经实现，见开发状态和已验证布局。下列章节保留完整需求与验收条件；剩余重点是主角性别联动、中文姓名实机显示、完整孵化与保存重载实测及其余特殊形态。

## 1. 连接与验证基线

用户已确认实机写入成功。当前正常关闭会释放客户端连接，Lua 继续监听，无报错属于预期行为；仍需用重新连接确认连接槽已经释放。写入中的关闭会等待任务结束，不强制中断。

补充副本上的验收记录：连接 → 关闭 → 重连；修改 → 读回 → 游戏内保存 → 重载；备份恢复；写入中断线。区分用户实测、自动化测试与推断。现有 73 项自动化测试和实际 ROM 函数对照作为回归基线。

## 2. 玩家训练师信息

新增独立“训练师”页：姓名、性别、公开 ID（TID）、隐藏 ID（SID），完整 32 位 ID 只作辅助显示。TID/SID 各为 0～65535；实际结构需以 ROM 核实。

先只读定位再开放写入。已有研究线索：SaveBlock2 指针 `0x0300500C`；读取完整原训练师 ID 的函数 `0x080CC1E4`。它们是继续核验的起点，不等于全部字段已经证明可写。姓名需核对改版字库、字符终止符、字节容量与中文编码；不能套用 UTF-8、GBK 或原版字符表，不能静默截断未知字符。主角性别需检查角色图像和剧情状态是否有联动，不能仅凭一个字节就宣布支持。

玩家资料和宝可梦 OT（原训练师）资料分开编辑。修改玩家 ID 不批量改写现有宝可梦的 OT；需要“归属当前玩家”功能时另设显式操作。新增事务必须扩展允许地址、旧值比较、备份及恢复校验，不能绕过现有保护。

验收：姓名往返编码；TID/SID 边界；玩家资料修改不触碰队伍和 PC；游戏内训练师卡、保存重载与恢复一致。

## 3. 单只宝可梦详细资料

第一批：亲密度、OT TID/SID、OT 姓名/性别；第二批：相遇地点、相遇等级、捕获球与来源信息；第三批：蛋状态及相关孵化数据。先实现队伍 100 字节结构，再逐字段核对 PC 58 字节压缩格式后开放 PC 对应功能。

蛋状态不能只翻转一位：已知有头部蛋标志与 IV 字段蛋标志，需要同时维护；还需核实亲密度字段在蛋状态下是否代表孵化周期，以及昵称、等级、招式和孵化流程的要求。提供普通个体→蛋→孵化的独立副本验收，不提供“坏蛋”开关。

地点从本改版 ROM 建立编号表，PokemonMemHack 的旧地点表仅作参考。保留不认识的原始值，不能默认改成第一个地点。OT ID 改动会影响闪光判定：预览清楚显示影响，默认尝试保留当前闪光、性格、性别、特性和已支持形态；约束不可同时满足时拒绝并说明，不暗中改变其他字段。

验收：范围检查、未知值往返保留、相邻打包位不变、OT 与 PID 联动、蛋标志一致、写后读回/恢复/保存重载。来源字段可编辑不意味着该遭遇真实存在；继续区分数值有效和完整来源合法性。

## 4. PID 与形态

已阅读用户指定的 [性格值资料](https://wiki.52poke.com/wiki/%E6%80%A7%E6%A0%BC%E5%80%BC)（页面版本 oldid=2579421）。该页介绍不同世代的 PID、加密常数及形态关系；这里仅作为候选机制索引，水银 FC 实现仍以本地 ROM 为准。后世代的独立形态参数、加密常数和闪光阈值不能直接搬入本改版。

建立形态机制表，按物种/形态内部 ID 区分：PID 派生外观、独立物种 ID、独立字段、持有物/战斗临时状态。UI 只列出本改版已核对且可以持久保存的目标。

实施顺序：未知图腾字形选择 → 晃晃斑花纹预览及显式重生成 → 已核实的独立形态 ID 映射。字形顺序也要对照游戏图像，不能只抄网络表。刺尾虫进化分支属于进化规则，不当作即时形态切换；一家鼠/土龙节节等后世代机制先核实本改版实现。

现有PID搜索默认保留未知图腾字形并拒绝晃晃斑PID改动；未知图腾指定字形和晃晃斑显式重新生成已实现，仍保留所选性格/闪光、性别及适用特性约束。不能为改变未知图腾字形仍强制固定整个低字节，否则可能错误地判定无解。明确所需不变量（性别、性格、特性、闪光），验证真实 ROM 的显示/读取函数后再开放。

## 5. 左图右数值界面

按用户描述参考 PokemonMemHack 的交互布局，不依赖旧程序在另一台电脑运行。

左侧：队伍六格与 PC 盒子切换、微缩图、名称/等级、闪光/蛋标记、清晰选中状态。PC 使用 30 格布局，空槽可见但不允许创建。右侧：基本资料、能力与 IV/EV、招式、来源/OT、蛋、形态等数值面板；保留检查预览、写入和恢复入口。

选中项以队伍槽或盒号/槽号绑定，不能只按物种 ID 绑定。未写入改动切换选择时明确处理；异步刷新不能让旧对象结果覆盖新选择。保留文本标签与键盘选择，图片缺失时仍可编辑。

微缩图优先研究从用户本地 ROM 提取到忽略的缓存，建立内部 ID→形态→图像/调色板映射；也可使用授权明确的资源。不要直接复制 PokemonMemHack 可执行文件资源上传。测试普通/闪光/蛋/形态、缩放、缺图回退与缓存重建；形态预览不是已写入状态。

## 推进方式

每阶段按“只读识别 → 编辑预览 → 带备份事务 → 自动化与独立副本实测”推进，每个可验收阶段单独提交。先稳固字段模型，再替换左侧选择界面，避免同时改变结构与选择对象逻辑。持续更新已验证布局及交接记录。
