## 喷雾 Var `0x4020`

两版 `0x0806E454` 实际变量指针函数返回 `gSaveBlock1Ptr(0x03005008)+0x1040`。样本的 SaveBlock1 指针是 `0x0202552C`，故当前样本地址为 `0x0202656C`。将隔离 CPU 的 SaveBlock1 指针单独加 `0x1000` 后，变量指针随之从 `0x0202656C` 移到 `0x0202756C`；**运行时不能固定写 `0x0202656C`**。section2 源指针 `0x030053C0` 的样本值是 `0x0202651C`，即 SaveBlock1+`0xFF0`；持久字段是 section2+`0x50`，恰好等于 SaveBlock1+`0x1040`。人工单独移动 SaveBlock1 指针不会自动改变 section2 源全局指针，因此两者关系必须作为事务守卫。

两版均通过 VarGet/VarSet 和隔离两字节干预：输入剩余步数 `0,1,2,100,200,250` 后调用实际入口 `0x080830B8`，得到 `0,0,1,99,199,249`；仅从 `1` 递减到 `0` 返回到期 `1`，其余返回 `0`。每例都检查 section2 源的两字节与目标值及递减结果一致，目标两侧各两字节未变化。道具步数实际 getter 核对为道具 `83→200`、`84→250`、`86→100`，非喷雾道具 `1/82/85→0`。两版各两个样本存档的 section2 字节与 `.ss1` 当前值 `0` 匹配：1.0 扇区 `0xA000/0x19000`，1.2 扇区 `0x8000/0x15000`。这不是修改后保存重载验证。

建议正式事务使用完整 ROM 身份、对齐且处于 EWRAM 的当前 SaveBlock1 指针、`source=SaveBlock1+0xFF0`、`target=SaveBlock1+0x1040=source+0x50` 联合守卫。提交时重读两个指针及两字节旧值；旧值超出已核验 `0～250` 范围则拒绝覆盖。保持写前备份、读回和条件恢复，不触碰背包道具。`game_fields_layout.json` 中的 `address` 只记录样本地址。

## 劲敌姓名

实际占位符 `0x080091E0` 对 `FD 06` 返回 `gSaveBlock1Ptr(0x03005008)+0x3A4C`；字段为 8 字节、最多 7 内容字节、`FF` 终止。两版旧记录均为 `0e 2c 0f 48 ff 00 00 00`，首个终止符后的合法样本填充是 `00`，不能要求尾部全为 `FF`。隔离写入 `A`、`abc1234`、`小智`、`小智A12` 后，实际对白展开 `0x08008FCC` 读取写后内容；超出字节容量和未知编码仍由 `name_codec.py` 拒绝。人工把 SaveBlock1 指针移 `+0x4000`，占位符与两条训练师名称分支均读取新地址。两条分支在训练师 `329/426/438` 的类别 `0x51/0x59/0x5A` 读该字段，普通训练师 `1` 不走劲敌分支。

两版 ROM 均找到 **10 组**连续字面量 `0x03005008` 加偏移 `0x3A4C`：`0x08009188`、`0x08054B50`、`0x08113470`、`0x08115138`、`0x08115180`、`0x08130458`、`0x081317F0`、`0x089A0048`、`0x08C5F338`、`0x08C606B8`。它们含对白/战斗等读取路径，也含写入者。实际 `0x08131754` 例程在隔离 CPU 的三个选择中，把三条 ROM 默认名写入同一 SaveBlock1 字段并补齐 `FF`；例如选择 0 把样本 `0e2c0f48ff000000` 改为 `0e2c0906ffffffff`。这是剧情或选择流程可能覆盖手工改名的证据，改名后不可承诺任何后续游戏事件都保留该名称。另三个扩展代码路径 `0x089A0018`、`0x08C5F308`、`0x08C60688` 在字段首字节为 `00/FF` 时填默认名；隔离测试确认首字节为合法非空名字时不覆盖。十组直接引用都指向同一字段，但间接脚本和缓存路径尚未穷尽。训练师表的固定阵容和玩家性别联动仍须分别核实。

两版 `.sav` 的两个校验有效 section4 均在 `+0xA7C` 与即时状态的字段及两侧各 64 字节相同：1.0 为 slot0/section12、slot1/section13（计数 190/191）；1.2 为 slot0/section10、slot1/section9（计数 216/215）。这是异时样本的静态对应，没有执行改名后保存/重载。正式事务应重读对齐且落在 EWRAM 的 SaveBlock1 指针与 8 字节原记录，要求非空、可解码且含 `FF`，写前再次比较指针和整条旧记录，保留完整备份、读回及条件恢复。ROM 身份只允许两个精确版本。

## 复跑

在仓库根目录，PowerShell 设置 `$d = '你的ROM与研究样本目录'`。对 `1.0` 和 `1.2` 分别运行；文件名按实际用户样本替换：

```powershell
$v = '1.0' # 再以 '1.2' 复跑
$stem = "宝可梦水银FC~致150年后的你 Version $v"
python tools/verify_box_names_repel.py (Join-Path $d "$stem.gba") (Join-Path $d "$stem.ss1") (Join-Path $d "$stem.sav") --report (Join-Path $env:TEMP "mercury-fields-$v.json")
python tools/verify_player_rival.py (Join-Path $d "$stem.gba") (Join-Path $d "$stem.ss1") --save (Join-Path $d "$stem.sav") --report (Join-Path $env:TEMP "mercury-rival-$v.json")
```

本次四条命令均退出码 `0`。运行依赖 `unicorn==2.1.4`，仅在隔离 CPU 中执行 ROM 例程。喷雾的 ROM 指针、两字节干预/VarSet、六组递减和道具矩阵，以及劲敌对白、两条战斗分支、十个直接字段字面量、一个 ROM setter、三个默认填充路径和重定位实验两版均通过。

## 仍需验收

本次共享工作树的正式事务自动化覆盖了两版内存及 Lua/TCP 回调，包含动态地址、过期指针/旧值拒绝、写前备份、读回与条件恢复；本研究期间单独执行的 `python -m unittest discover -v` 为 **293 项通过（45.332 秒）**，最终版全量结果由主代理最终检查点记录。这些测试使用隔离内存和模拟 Lua/TCP，没有连接运行中的 mGBA。游戏内喷雾到期消息、重新使用喷雾、劲敌全部相关对白/菜单及战斗显示、**ROM setter 在实际剧情中的触发条件**、改值后保存重载仍需人工在独立副本上测。两版 `.sav` 与 `.ss1` 的静态一致不构成这些测试。劲敌姓名的源码事务已启用，当前仅源码、未发布；玩家性别、角色缓存重建及剧情阵容选择继续保持只读，不能因劲敌姓名字段通过而一并开放。
