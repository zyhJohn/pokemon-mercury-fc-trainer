## 修复「一键启动无效」+「mGBA -g 无反应」

- 用户反馈：①`启动修改器.bat` 一键启动无效；②`mGBA.exe -g "游戏.gba"` 启动后无反应。
- 排查结论：
  1. **mGBA 本身正常**：`mGBA.exe -g` 启动后窗口标题 `mGBA - POKEMON FIRE - 0.10.5`、进程 Responding=True、GDB 端口 2345 正常 LISTENING。所谓「无反应」其实是 mGBA 停在**标题画面**等用户按键进游戏（进入游戏后 `gSaveBlock1Ptr`(0x03005008) 才被赋值为 0x0202552C，之前读是 0）。
  2. **一键启动失效根因**：bat 里 `start "" mGBA.exe -g "%ROM%"` 中 ROM 文件名含**空格+中文**（`宝可梦水银FC~致150年后的你 Version 1.0.gba`），`start` 命令对含空格路径解析不可靠，报「系统找不到文件 \\。」。修改器 exe 那条 `start` 反而能成功（无额外参数）。
  3. 附带坑：bat 中文 echo 在 GBK 代码页下乱码；`timeout /t` 在部分环境被拆参数；ps1 若含中文且无 BOM，Windows PowerShell 5.1 按 GBK 读会乱码报「字符串缺少终止符」。
- **最终方案**：`启动修改器.bat` 改为一行 `powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0启动修改器.ps1"`；新增 `启动修改器.ps1`（**纯 ASCII**，用 `Start-Process` 分别启动 mGBA `-g` 和修改器 exe，规避 start 引号坑 + 编码坑）。
- 已实测：bat→ps1 端到端启动成功（mGBA 进程 + 修改器窗口 `宝可梦水银FC 修改器 (mGBA)` + GDB 端口 2345 监听）。
- 关键经验：**Windows 上启动脚本优先用 PowerShell（Start-Process）而非 bat 的 start 命令**；脚本文件若要兼容 PowerShell 5.1 须纯 ASCII 或带 UTF-8 BOM。
- 已同步：`pokemon-mercury-fc-trainer/` 下更新 `启动修改器.bat` + 新增 `启动修改器.ps1`，README.md 补「常见问题」与启动说明。

## 新增「无 GDB」连接方式（Lua 内存桥接）

- 用户诉求：不想用 GDB（需 cmd 启动 mGBA，麻烦）。
- 方案：写 `mercury_bridge.lua`——mGBA 内置 Lua socket 库（`socket.bind/listen/accept/send/receive`）+ `emu:read8/16/32/write8/16/32/readRange`，在 mGBA 内监听 TCP 端口（默认 8888，被占用 +1），提供纯文本内存读写协议（`READ/READ8/16/32/WRITE8/16/32/WRITE/PING`，换行分隔）。
- 修改器 `trainer_gui.py` 新增 `MemClient` 类（同接口 `r8/r16/r32/w8/w16/w32/read/write`），`App._do_connect()` 优先连 TCP 桥接（从 8888 起向上扫描 + PING/PONG 握手），失败回退 `GDBClient`。
- 关键坑：mGBA **无脚本自动加载机制**（无命令行参数、无配置项），脚本只能 `Tools -> Scripting -> File -> Load Script` 手动加载一次（加载后常驻直到关 mGBA）。
- 验证：Lua 语法用 lupa（`trainer_work/venv-build` 装了 lupa 2.8）`load()` 编译通过；协议用 `trainer_work/mock_bridge.py`（Python 模拟桥接服务）端到端跑通（金钱118464/代币5/队伍/背包读写全对）。
