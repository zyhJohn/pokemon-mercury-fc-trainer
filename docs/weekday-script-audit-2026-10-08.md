# 星期事件脚本与显隐位核验（2026-10-08）

## 结论

[宝可梦水银百科的时间事件表](https://sum-light.github.io/azoth-wiki/events/)列出八项星期日内容：满金地下通道中药店、弟弟理发、37号道路星琪天磁铁、百货店6F抽奖、酒吧聂梓、擂钵山弃世猴、百货店5F的招式学习器21/27、满金大厦偶像。本次对两版实际 ROM 追到了**擂钵山一处星期对象的可验证候选**；其他七项还没有事件脚本与 flag/var 的闭环映射。该网页称资料来自 Flag&Var 表，但页面本身不列字段编号，因此不能用网页名称代替 ROM 写入证据。抓取的页面原文 SHA-256 为 `63c311abb244f32466c7879b171a936aa4f01d6079f1482957007278ae853178`，私人副本在被忽略的 `diagnostics/` 中。

当前**没有可安全开放的“清除周日领取位”操作**。旗标 `0x1898` 参与擂钵山对象显隐，V1.0 的日期回退确实可能阻止其星期更新回调被安排；但 `0x1898` 还出现在事件脚本清位分支，且同组其他星期对象旗标在对象脚本中也会被设置。单靠星期值不能判断该对象是否已互动、是否应重新出现。原用户所见“其他日期仍显示周日内容”与日期门槛阻断一致，但完整原因和八项活动结果仍需地图与保存重载实测。

## opcode、入口与消费者

两版 opcode 表 `0x0815F9B4` 中，`0x25` 对应 `0x08069EFC`，`0x26` 对应 `0x08069F3C`。实际 handler 分别读特殊函数编号；`0x26` 先读输出变量，再调用 `GetVarPointer` 并存储返回值。特殊函数表 `0x0815FD60 + 0xDA*4 = 0x081600C8` 指向星期 getter（V1.0 `0x09D59704`；V1.2 `0x09D5D8B8`）。全 ROM 的 `special 0xDA` 原始字节候选只有 `0x0947683E`，周围不是已验证脚本边界。`specialvar *, 0xDA` 有 `0x08714BDF`、`0x099DA395` 两处原始候选，但输出变量分别是 `0x10E2`、`0x0133`，两版实际 `GetVarPointer` 均返回空指针。**尚无可信的地图脚本直接调用 special 0xDA**，故没有在这些匹配附近猜测比较、跳转或领取位。

实际星期消费发生在原生回调路径：

| 路径 | V1.0 | V1.2 | 作用 |
| --- | --- | --- | --- |
| 每日入口 | `0x09D64C04` | `0x09D68FD8` | 以参数 0 查询 Var5009；通过时把后续回调地址写入事件记录 |
| 回调字面量 / 目标 | `0x09D64C58` → `0x09D631A4` | `0x09D69044` → `0x09D67520` | 回调处理记录中的日期/计数、Var5009/500A 及大量事件变量/旗标 |
| 读取 `gClock+5` | `0x09D6384E` 起 | `0x09D67C20` 起 | 星期日 0～星期六 6，按日条件调用 ROM 的 `FlagSet` |
| FlagSet / Clear / Get | `0x0806E680` / `0x0806E6A8` / `0x0806E6D0` | 同左 | 已核实际位运算；`FlagSet` 对对象为隐藏语义 |

回调中的直接星期比较涉及 `0x1890`（周四 4）、`0x1894`（周五 5）、`0x1898`（周日 0）、`0x18B9`（周六 6）。这些不是“按星期自动可清的领取位”清单：同一回调还处理大量变量与其他旗标，脚本也能修改其中的位。V1.0 与 V1.2 的回调后续分支不完全相同。

以下链条均由两版实际 ROM 的对象模板 `flagId`、对象数组、地图事件指针、地图 header 的 region section，以及项目已核对的地点名称共同验证。

| 显隐 flag | 对象模板 / 脚本 | 地图、对象 | 页面上的候选 |
| --- | --- | --- | --- |
| `0x1894` | `0x08A193EC` / `0x08F34F0B` | 连接洞，对象 localId 12，坐标 (32,36) | 周五拉普拉斯 |
| `0x1898` | `0x08B14B3C` / `0x08F353B3` | 擂钵山，对象 localId 3，坐标 (6,6) | 周日弃世猴 |
| `0x18B9` | `0x08A30D80` / `0x08F3FB98` | 龙穴，对象 localId 7，坐标 (52,35) | 周六园陆鲨 |

连接洞对象脚本 `0x08F34F2E` 明确执行 `setflag 0x1894`；龙穴对象脚本 `0x08F3FBB9` 执行 `setflag 0x18B9`。擂钵山的 `0x1898` 另有被指针 `0x08F34FCC` 引用的有效脚本片段 `0x08F35048: clearflag 0x1898; end`。这说明 flag 的使用范围超出单纯星期比较；该脚本片段的触发前置尚未完整解析。擂钵山模板和网页事件的对应有地图/星期双重支持，具体交互或捕获状态仍未闭环。

## 隔离 CPU 验证与反例

`tools/audit_weekday_scripts.py`用精确 ROM SHA-256 限定两版，读取各自 `.ss1` 作隔离 RAM 起点；仅跳过 RTC 硬件刷新以保留注入的日历。模拟 2026-10-04 周日至 10-10 周六，分别从上述四位全 0 和全 1 出发，实际执行回调并用 ROM 的 `FlagGet` 读回，共每版 14 组。下表是 `0x1898` 的结果：

| 当前星期 | V1.0：旧位 0 / 旧位 1 | V1.2：旧位 0 / 旧位 1 |
| --- | --- | --- |
| 周日 | 0 / 1 | 0 / 0 |
| 周一至周五 | 1 / 1 | 1 / 1 |
| 周六 | 0 / 0 | 1 / 1 |

V1.0 周日保留 `0x1898` 旧值，周六另一分支清位；V1.2 周日明确清位，其他日期设置为 1。这是实际回调在构造记录条件下的行为，不能视为独立清位事务的授权。另以“周五、通用记录在未来周日、旧 `0x1898=0`”执行实际每日入口：V1.0 在日期检查后直接返回，V1.2 通过日期门槛；入口本身均未直接改变 `0x1898`。这说明 V1.0 在日期回退时可能继续保留先前周日的可见状态，现有 Var5009/500A 修复可以重新开放每日回调路径，但对具体对象何时更新还要等游戏流程执行。

可复现命令：`python tools/audit_weekday_scripts.py <ROM.gba> <STATE.ss1> --profile <rom_profile.json> --output diagnostics/weekday-scripts-v10.json`；V1.2 换对应配置与输出名。两版各 14 组与静态指针/handler/脚本断言通过，私人 JSON 报告被 Git 忽略。工具没有默认 ROM/存档路径，也没有修改运行中的游戏或原始文件。

## 尚需验收

需要按用户实际游戏中的八项周日内容逐项记录对象是否出现、对话/领取或战斗结果，并在周日→周五/周六→周日的地图重入与游戏内保存重载后复核。对 `0x1898` 特别需要追完 `0x08F35048` 的上游分支及擂钵山对象交互脚本；对百货店、酒吧、地下通道和大厦还要建立地图对象/脚本到旗标或变量的映射。当前只能提供只读诊断与候选定位，不能无条件清 `0x1898` 或其他领取位，也不能把一个显隐对象的结论推广到所有星期日事件。
