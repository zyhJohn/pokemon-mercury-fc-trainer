# 未收录 ROM 的兼容识别 · 2026-10-14

源码版本 `0.2.16-dev`。本轮替换“完整 CRC 不在白名单就拒绝”的连接入口，保留 V1.0、V1.2、V1.33 原版快速识别。其他文件不按名称或小版本号判断；分别检查三个已核验基线的编辑契约，唯一匹配后显示“结构兼容 · 基线 V…”。基线名称不是当前 ROM 的真实版本号。

此机制适用于 1.0x、1.1x、1.2x、1.3x 和后续文件的检查入口，但不意味着这些版本全部已验证。改变版本标签或受保护范围外的素材，不必增加完整文件白名单。新增代码、表结构或数值变化仍需扩展契约，不能凭版本号放行。

## 识别内容和边界

兼容摘要仅包含地址、长度及 SHA-256，不包含 ROM 字节。由原版 ROM 与配置提取器的读取记录重建，可用 `tools/extract_profile.py --compatibility-manifest` 复现。运行时同时检查基线配置自身的指纹，避免代码与配置数值不对应。

保护范围包括：

- 基础引擎 `0x08000000..0x08400000`、扩展引擎 `0x09CCD000..0x0A000000`；保留代码、字面量、创建/压缩/形态及保存相关依赖。GBA 标题 `+0xA0..+0xAC`、修订及头部校验字节 `+0xBC..+0xBE` 除外。
- 任务代码/记录区 `0x08DF0000..0x08E40000` 和额外接取旗标表；保护静态支线进度解释。
- 正常/小中文字体槽 `0x087D0000..0x088B0000`；防止字体字形重排与姓名编码不对应。
- 配置提取实际访问的物种、招式、道具、经验、学习器、等级招式、地点、图像指针和其他映射表。

本轮采用保守策略：受保护区域必须与某一基线相同，种族值、PP、特性、道具价格等参数变化会明确拒绝；尚未实现未知数值表的自动重提取。受保护区可能含文案或素材，不能宣称所有文本/贴图修改都能通过。范围外的修改也不代表游戏全部行为经过验证。

首次识别进行完整保护区核验；常规刷新检查当前 CRC 与既有代码特征；每次写入前重新核验完整保护区。检查前后 CRC 必须一致。mGBA 的 CRC 是载入文件身份，不是任意运行时 ROM 热补丁的校验值；分段读取也不是整个 ROM 的原子快照。原有 Lua 回调中的目标旧值、指针、代码特征、战斗状态及 CRC 比较继续保留。

## 身份、诊断与桥接

`rom_sha256` / `layout_sha256` 用于选取基线布局；`rom_identity` 用于实际文件隔离。已知原版继续使用历史裸 SHA，保留既有盒锁。兼容在线文件用实际 CRC 身份，本地文件用实际 SHA 身份；备份、引用、预览、快照与盒锁不能跨身份复用。兼容文件不能恢复仅记录原版布局 SHA 的旧备份。

RTC 文件操作必须重新选择本地 ROM，核对 `actual_rom_sha256`，不能用在线 CRC 代替本地文件 SHA。兼容在线身份与本地身份分别保存，不自动把两种来源的记录互认。

失败连接诊断保留修改器版本、端口、桥接能力、实际 CRC、失败阶段及各候选差异，失败重连不再把上一连接配置当作当前配置。诊断仍保存在本地，不入库。

新桥接增加只读 `ROMREAD` 能力，`READROM` 单次最多 64 KiB，只允许 ROM 地址；旧桥接回退为 4 KiB `READ`。普通 RAM 读取和所有写入事务容量不变。完整解压新检查包并重载 `mercury_bridge.lua` 可减少兼容检查的往返次数；真实 mGBA 吞吐尚未测量。

## 验证与交接

`tools/verify_rom_compatibility.py` 用用户自行提供的精确原版 ROM，在内存副本中测试标题和图标变化通过、核心代码和物种参数变化拒绝，比较离线与 ROM 支持的只读读取器结果，并重建摘要。它不写 ROM、存档或模拟器内存，不代表实机保存重载。

```powershell
python tools/verify_rom_compatibility.py '你的原版.gba' --lua-tcp --report diagnostics/rom-compatibility.json
python -m unittest discover -v
python trainer_gui.py --self-test
python tools/build_release.py
```

本轮实际结果：完整 `python -m unittest discover -v` 共322项通过、无跳过（58.108秒）；关键错误检查及源码启动自检通过。三基线各163段摘要重新生成一致，保护8,977,570/8,977,597字节。三份原版的内存副本各4种变化、离线与ROM支持的读取器共24个接受/拒绝结果符合预期；各自实际Lua/TCP与模拟RAM的写入、读回、恢复及数值表热改拒绝通过。此处未连接真实mGBA，也未修改用户游戏、ROM或存档。

当前没有获得反馈用户修改版的实际文件，因此尚未验证该文件能否通过本轮契约。若仍被拒绝，以诊断中的类别和地址定位具体修改，不能重新改成只改 CRC 放行。
