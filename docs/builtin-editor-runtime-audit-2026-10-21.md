# 内置修改器旧版移植：隔离运行核验

2026-10-21，承接[静态移植研究](builtin-editor-port-research-2026-10-21.md)。本轮将候选构造和运行验证整理为仓库工具，实际执行注入指令及原引擎函数。当前应用仍为0.2.18-dev，只登记已核验的1.33原补丁变体；1.0/1.2仍是研究候选，没有新增运行时放行条目。

## 可复现工具

- `tools/builtin_port_candidate.py`：严格核对原ROM、1.33模板和原UPS完整身份、所有写入原像及分配区，作1.0两项重定位，在内存生成候选与各自UPS。报告包含模板、输入补丁、候选和衍生UPS身份；不输出二进制文件。
- `ups_patch.encode_ups`：增加通用UPS编码，支持等长/变长、尾部差异和显式反向恢复；输入为不可变bytes。
- `tools/verify_builtin_menu.py`：绝对地址Thumb执行夹具、只读ROM、明确记录的BIOS服务和即时DMA模型；执行原生菜单任务、分配、调度及释放。默认不替换原生函数。
- `tools/verify_builtin_actions.py`：实际确认处理函数及原生个体读取、写入、能力重算、道具和PC压缩/解压；UI绘制、延时及预览分配替身逐项记录。详细RAM差异只存本机忽略目录。
- `tools/verify_builtin_relocations.py`：逐版本原生名称getter对照、实际payload间接调用及图像索引/指针探针。
- `tools/research_report.py`：原子写JSON，拒绝报告覆盖输入路径、符号链接或硬链接别名；序列化失败保留原报告。

上述执行工具依赖`unicorn==2.1.4`，已列入`requirements-dev.txt`；它不属于便携程序运行依赖。私有ROM及即时存档由用户指定，跨版RAM夹具必须单独标记。输出报告放在`work/`或`diagnostics/`，不得提交。

示例参数均是用户选择的本机路径，不是程序默认值：

```powershell
python tools/builtin_port_candidate.py <1.2原ROM> <1.33原ROM> <原1.33UPS> --report work/candidate.json
python tools/verify_builtin_menu.py --rom <1.2原ROM> --template-rom <1.33原ROM> --ups <原1.33UPS> --state <对应即时存档> --cycles 5
python tools/verify_builtin_actions.py <目标原ROM> <1.33原ROM> <原1.33UPS> <即时存档> --report work/actions.json
python tools/verify_builtin_relocations.py --rom-v10 <1.0原ROM> --rom-v12 <1.2原ROM> --rom-v133 <1.33原ROM> --ups <原1.33UPS> --report work/relocations.json
```

## 已核验的重定位

三版名称输入矩阵分别为8071、8069、8068组，共24208组。每组在原ROM和对应补丁候选实际执行一次，对照返回指针、32字节读取、名称和终止符状态，差异/执行错误均为0。覆盖profile全部普通/第二/隐藏非零特性来源、0～300名称编号的11个上下文，以及特性129的1554个物种上下文。这不是所有特性编号均允许编辑的声明。

每版另执行13个完整payload名称路径，hook实际确认读取`08A7F96C`后进入本版getter。1.0两处重定位确实生效；1.0保留自身名称规则，1.2/1.33保留四个物种的特性129“锋锐”分支。图像路径实际读取1.0的`097BB0A0`或新版的`097BB0A4`，有效资源通过原压缩头验证后到达BIOS解压包装入口；此探针在包装入口停止，不冒充完整绘制验收。

主控另独立运行公开候选构造：两版CRC/SHA与静态研究一致，严格UPS正反恢复逐字节一致；每版源文件改一字节、模板改一字节、UPS改一字节及误用1.33源均拒绝。检查后重新读取所有输入，确认未变。

## 菜单生命周期

三版各在同一个隔离CPU连续打开/关闭5轮，每轮进入宝可梦、背包及其他三个菜单再返回，验证左右页签循环、原生堆释放及堆完整性检查。每轮39次调度进入可输入状态、22次调度完成退出，未安装原生函数替身；这些是夹具调度次数，不是实机帧时序测量。

1.2从匹配原ROM的背包即时存档执行伤药场外回调、异步入口及脚本边界。1.0样本未打开背包，其背包专用指针为空，不能直接调用伤药回调；已改从明确的原生脚本边界验证，未声称1.0伤药完整入口通过。1.33使用1.2 RAM移植夹具并显式重置任务，从原生脚本边界执行，不是独立1.33游戏快照。报告逐项标注这些前提。

`08A7A05C: BX r0`的两个已发现调用上下文已定位为加密字符串CRC失败分支。三版正常getter不进入该分支；只在内存扰动加密源单字节后，实际走到r0=1、跳转地址0。此结果闭合两个已知调用上下文的分支条件，不证明不存在其他调用者，也不判定真实BIOS中的最终行为。

## 验收边界与后续

Unicorn执行证明实际指令路径和此夹具中的RAM结果，不能代替mGBA全机时序、BIOS保护、开放总线、地图/战斗、旧存档加载、保存后关闭重开、外置野生覆盖并用和真实显示。无BIOS映射时的NULL读取错误不能直接写成实机必然崩溃。

原补丁已观察到闪光显示使用`XOR <= 8`，游戏原生及外置修改器使用`XOR < 8`；研究保留差异，不静默修正原UPS。名称的字符串格式验证也不等于语义编号合法性，例如1.0的301号可能读到名称表外的数据。

图像空项已经以三版原生按键回调复现：在已激活的种族编辑上下文，从1293按Down到1294、从1544按Up到1543，原验证接受编号，刷新进入图像函数后预读NULL；无图像替身。从1553按Down仍保持1553，1554及更大值仅作为直接探针，不能声称菜单可选。此测试上下文由夹具构建，不等同完整菜单入口到该物种的人工操作验收。

满重要道具口袋使用75个不同合法ID、数量1占满，再添加第76个合法ID；三版候选及各自未打补丁原ROM均进入同一错误空位索引。原扫描返回`0xffffffff`，调用方截成16位后仍与32位失败值比较，最终尝试写`0207C224`。该地址超出夹具EWRAM映射，但真实GBA有镜像语义，不能据此宣称实机必然崩溃；它不是旧版重定位特有回归。数量1000/65535的定向handler探针同样不能当作菜单允许输入范围。

## 独立安全修复候选

新增两个显式payload修复，原UPS和原移植候选的身份均保留：

| 模块 | 改动范围 | 行为 |
| --- | --- | --- |
| `tools/builtin_image_guard.py` | `08A7D572`、`08A7D59C`各4字节；完整`08A7FD00..08A7FD80`新代码区 | 绘制前检查索引不超过1553及表项非空，图像、普通/闪光调色板分别回退条目0；不改ctx中的物种编号。 |
| `tools/builtin_bag_guard.py` | `08A7BD60`调用指针；完整`08A7FE00..08A7FF00`新代码区 | 调用本版原生ID验证及口袋映射，检查描述符范围和容量，存在同ID或空槽才调用原AddBagItem；满包无同ID返回0。 |

两模块严格核对三份原研究对象完整SHA、调用点原像及各自完整FF代码区。`tools/builtin_safe_candidate.py`从同一base分别取得两个plan，先检查全部原像、等长、范围及不重叠，再一次合并，生成独立UPS并严格正反恢复；CLI只输出JSON，不导出补丁或登记支持。

图像模块三版合计13986项helper执行，所有非空表项保持原指针，空项回退0且ctx保持；66次完整绘图函数、18次原生按键callback均返回。完整函数实测经过图像及调色板两次BIOS解压服务模型，不安装原生函数替身。寄存器、栈和两续点条件码使用已独立审查，合成测试覆盖两个入口、边界及NULL。

背包保护显式将允许发放量限定为1～99，0返回失败。真实菜单按键已测到99封顶、归零及回到1，1.0/1.2/1.33共享该payload；不会把定向handler能接收65535当作正常UI能力。原生同ID加到999成功、超过999返回失败的规则保持，不增加拆栈行为。新的保护不修改游戏原生AddBagItem及现有外置事务代码。非法描述符、跨度及32位加法回绕也有拒绝测试。

公共完整图像复现工具为`tools/verify_builtin_image_guard.py`，可直接对合并安全候选检查三张表、完整绘制和原生按键。背包运行验证由`tools.verify_builtin_actions.verify_bag_guard`暴露，接受合并后的image和明确的`field_entry`/`reset_tasks`夹具参数。更改payload形成独立研究身份，完成真实游戏保存重载等验收后，才导出正式旧版UPS并登记完整契约。

### 合并后的实际验证

主控通过公共构造器及验证函数重新执行三版合并候选：各自完整配置除真实SHA/CRC外一致，提取读取次数为41967/41983/41983，各90项原事务、未知图腾及野生控制守卫保持。每版2轮完整菜单开关、4662项三表helper、22次完整绘图、6次原生按键callback及15项背包集成检查均通过。背包独立worker随后增加描述符负例的矩阵为每版18项通过；两组计数分别保留，不将它们混为同一次主控执行。

背包原ROM与原候选对照增加显式的首个EWRAM别名写模型，实际观察到`0207C224/0207C226`写入转发到`0203C224/0203C226`，原函数仍返回成功，改动相邻普通道具末格；该模型不是完整双向镜像或全机硬件模拟。安全候选相同满包输入返回失败、无别名写；合法成功仅改变预期口袋4字节，除调用栈外无关RAM保持。真实菜单按键从顶部进入背包、选择182、数量99→0→1再确认的路径，三版安全候选均正常拒绝满包。1.0从脚本入口；1.33明确使用1.2 RAM且重置任务，旧未重置时的PC0夹具失败报告另存。
