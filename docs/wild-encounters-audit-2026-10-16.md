# 后续野生遭遇物种/等级：ROM 审计（2026-10-16）

本研究只读取用户本地三版水银 FC ROM/即时存档，在隔离 Unicorn ARM CPU 内执行真实 ROM。研究工具不会连接 mGBA，也不会写 ROM、存档或即时存档。生产覆盖数据由 `wild_encounter_data.py` 与 `wild_encounter_layout.json` 给出。

## 定位与最小实现

三版并非简单照搬原版 FireRed。`080829FC` 的原野生生成入口已跳转到本改版生成器，`08082CBC` 的普通遭遇入口也已跳转。旧 `08082AEC`/`08082B64` 的原版抽签函数不是当前普通/钓鱼路径的充分依据。

| 版本 | 本改版完整生成器 | 普通生成函数 | 钓鱼函数 |
|---|---|---|---|
| 1.0 | `09D64798..09D6495B` | `09D64D10..09D65003` | `09D65DF8..09D65E9F` |
| 1.2 | `09D68B6C..09D68D2F` | `09D69104..09D693F7` | `09D6A1EC..09D6A293` |
| 1.33 | `09D6BA78..09D6BC3B` | `09D6C010..09D6C303` | `09D6D0F8..09D6D19F` |

没有在已追踪调用链中确认可直接安全设置的“野生物种/等级覆盖”原生变量。最小实现采用仅在模拟器当前 ROM 内存中的两处可撤销覆盖，共 112 字节：

1. 本改版生成器前 12 字节替换为 `push {r3}; ldr r3,[pc,#4]; bx r3; nop; .word stub|1`。
2. 三版共同空白区 `08A8C000..08A8C063` 写入 100 字节 Thumb stub。

stub 先恢复临时保存的 r3，再执行原始 `push {r4-r7,lr}`。只对精确六个调用返回地址覆盖 r0=物种、r1=等级；r2=抽签槽、r3=首/次敌方生成标记保留。随后重放原始前 12 字节余下指令，返回本版生成器 `entry+12`。全部 PID、性格、能力值、经验、技能、PP、特性、昵称等仍由改版原生函数创建。

六个调用点包括普通生成函数的四条分支与钓鱼函数首只/第二只的两条分支。白名单存储的是 `BL 地址 + 5`（Thumb 返回地址的低位保留），详见 JSON 的 `callers`。生成器其他调用来源不覆盖参数。脚本、固定事件、漫游、训练师和其他未列入来源均不应展示为已支持。

最初考虑复用被替换的旧函数体；独立复核发现 ROM 数据中存在指向该范围的原始字节匹配，无法完全证明无动态入口，因此最终放弃该候选。

## 空白区域与布局保护

最终 stub 区位于三版共同全 FF 区 `08A8B58C..08A92EDB` 内。对每版完整 ROM：

- stub 原始 100 字节均为 FF。
- 每字节对齐扫描 32 位值，指向 stub 的原始指针匹配数为 0。
- 能够到达 stub 的 Thumb BL 扫描匹配数为 0。
- stub 前后各 2048 字节均为 FF，排除附近 Thumb B/Bcc 静态跳入。

这些结论绑定完整 ROM SHA-256，并由 `verify_stub_padding` 复现。结构兼容 ROM 仍须逐次比较 stub 原始 100 字节与本功能额外特征，不允许仅凭已有通用结构检查覆盖这片区域。

每版 JSON 另外提供 14 个长度不超过 128 字节的 `guards`：两个原入口跳转、完整生成器、完整普通生成函数和完整钓鱼函数。`expected_hex` 可直接用于 Lua 无 SHA 库的逐字节检查。已启用时只允许对本会话精确记录的 overlay 字节作规范化；真实 ROM 身份与基线布局身份继续分开，不能全局跳过 ROM 检查。

## 生产接口

```python
build_wild_patches(profile, species, level)
# -> tuple[(address: int, before: bytes, after: bytes), ...]，恰好两项

wild_layout(profile)
# -> 独立配置副本，按 layout_sha256（否则 rom_sha256）选择布局
```

只接受整数、有效 profile 物种且位于核验有效编号段，等级 1..100。拒绝 bool、空洞编号与未知布局。JSON 同时提供 `hook_template`、`stub_template`，模板默认物种/等级均为 1；`stub_species_offset=48` 为 u32 小端数，`stub_level_offset=26` 为 u8 立即数。除这两个参数位置外，stub 必须与本版模板完全相同。固定原始 hook 与 stub 字节不能由客户端任意传入。

物种表地址为 `0976DFBC`，记录长 28，三版有效物种均为 1432 项，但编号不连续，最大 1553；应以 `valid_species_ranges` 明确拒绝空洞，不能仅以最大编号验证。

## 实际隔离 CPU 验证

最终 `08A8C000` 方案每版均通过以下检查：

| 检查 | 每版实际结果 |
|---|---|
| 5 组物种/等级 × 6 白名单调用点 × 首/次敌标记 | 60 组通过 |
| 完整敌方 600 字节与未覆盖 ROM 按目标参数生成比较 | 上述 60 组逐字节一致 |
| 8 个非白名单原生直接调用点 | 8 组原始参数/600 字节保持一致 |
| 完整普通生成链：陆地、水面、碎岩 | 3 组输出物种 25、等级 37 |
| 1432 个有效物种、固定初始内存、等级 37 | 1432 组通过，能力值与对应物种数据一致 |
| 上述生成过程的玩家队伍 600 字节 | 完全不变 |
| 同一 CPU 先执行覆盖，再还原两区并再次生成 | 恢复原生物种/等级，完整敌队与未覆盖原生一致 |

60 组包含 1 级、100 级、未知图腾和脱壳忍者。首/次敌标记验证分别生成第 1/2 个敌方记录。独立复核另外覆盖了调用点邻居、r2 不同槽位、连续双敌生成及整个 EWRAM 的原生对照。

实际发现并保留了原生形态调整：物种 1141/1193（颤弦蝾螈两种形态）会根据原生随机性格互换。界面应说明“形态按游戏原生规则调整”，不能承诺覆盖最终形态与指定编号永远相同。

1.0、1.2 使用各自用户本地 ss1 的 RAM 作为种子。1.33 当前没有 ss1，使用 1.2 RAM 种子执行 1.33 ROM，报告明确标记 `synthetic_cross_version_memory_seed=true`；这不是 1.33 实机状态验收。

报告位于忽略目录 `diagnostics/wild-encounters-{1.0,1.2,1.33}.json`。可复现命令：

```text
python tools/audit_wild_encounters.py <本地ROM.gba> <本地状态.ss1> --all-species --report diagnostics/wild-encounters.json
```

Unicorn 对已经翻译执行过的代码需要显式 `ctl_remove_cache`，否则 `mem_write` 恢复代码后仍可能使用旧翻译块。恢复验证已先执行覆盖，再恢复并清理研究 CPU 翻译缓存。此维护步骤不能证明 mGBA 的运行期 rawWrite 行为；后者须单独验证。

## 生命周期与支持边界

- 开启：在非战斗状态确认 ROM 身份、额外特征、原始两区与 PC 安全位置，在同一 Lua 回调原子安装两区，读回后报告启用。
- 更新：仅允许本会话精确 overlay 作为旧值；更新参数时继续比较两区和 ROM 身份，避免覆盖用户另有补丁。
- 关闭/断线：在同一 ROM 身份、两区仍精确等于本会话 overlay 时条件恢复。Lua 应有本地租约，不依赖 Python 正常关闭才恢复。
- ROM 切换：不向新 ROM 写旧布局恢复数据；由 bridge 的 ROM 生命周期处理旧 overlay 与本地租约，清除旧控制状态。
- 启用、更新、关闭、租约恢复时若 PC 落在入口 12 字节或 stub 100 字节内，应延后操作，不能在 stub 执行中途复原旧码。
- 仅保证已核验普通生成与钓鱼调用。战斗已经开始后不改当前敌方数据，不改玩家队伍，不将入队/战后改物种称为下一次遭遇控制。
- 不改变遭遇概率；未出现正常野生遭遇时不会主动强制开战。
- 喷雾与先行特性过滤位于生成器调用之前，仍依据本次原生抽签条件运行；本覆盖不会强制穿透喷雾。指定的等级进入完整原生生成阶段。
- 原生形态、性格、特性与来源规则继续运行；不声称自然可捕获来源合法性。

## 生产桥接的补充验证

`tests/test_wild_control.py` 的22项测试使用实际Lua解释器及合成ROM/RAM夹具，部分通过真实TCP运行完整桥接。覆盖专用命令、物种/等级/CRC/nonce、PC忙碌延后、帧租约、生产EOF与reset回调、覆盖所有权读回、连接代次和并发RPC响应配对。它们没有启动真实mGBA。

停用维护精确逐字节恢复账本：先恢复12字节入口并完整读回，才恢复100字节stub。一次写前、写后或读回异常各遍历112个位置，在同一回调有限重试后全部恢复，再返回成功；持续入口单点故障则将本次已恢复前缀条件回退为完整有效覆盖，保留停止中错误状态，由帧回调重试。持续stub故障时入口已完整恢复，不再跳转stub。第三方写入即使恰为before/after之一，也不能越过精确账本检查。唯一尚未确认的本次写入地址单独记录，不放宽其它字节的所有权。

双重故障导致入口既不能恢复也不能回退时，仅保留错误与恢复账本，不能保证CPU继续执行安全；应重新载入ROM。未使用未经核实的暂停API。强制卸载/销毁Lua环境后帧租约也不再运行，须在卸载脚本或读取即时存档前先关闭该功能。

尚未验证：实际 mGBA ROM rawWrite 的取指刷新与恢复、真实地图步行/冲浪/碎岩/钓鱼战斗全过程、捕获后保存/加载、真实断线/切换ROM的模拟器生命周期、所有剧情特殊遭遇。隔离CPU和Lua/TCP结果不替代这些验收。

命名定位参考 [pret 原引擎 wild_encounter.c](https://raw.githubusercontent.com/pret/pokefirered/master/src/wild_encounter.c)。所有可写地址、入口、参数和覆盖字节结论均以本地三版改版 ROM 与隔离 CPU 结果为依据。
