# 内置修改器补丁兼容核验 · 2026-10-21

本轮检查版为0.2.18-dev，工作分支`codex/builtin-editor-compat`。现已核验用户提供的1.33内置修改器UPS；原版1.0/1.2/1.33继续使用各自配置。没有将补丁CRC加入原版快速白名单，也没有把1.33布局当成其它版本。

## 输入和反馈对应

| 对象 | CRC32 | SHA-256 |
| --- | --- | --- |
| 原版1.33 | `518482f7` | `9801866280284a8ac12650666b8526ff3d07aa455f8dc623c2c56c0537313ec4` |
| 用户UPS（23847字节） | `441dcd67` | `63d3c2cdbd70cb5821c4942b253fe3bfa4ef91d93679606b6f15e340a9e9b33c` |
| 内存中重建的补丁版 | `51553df6` | `248094b36152be1db91357e0cdfa1a583bfe79676c7129b274c1c605b4c615c0` |

输入、输出均33554432字节。UPS输入/输出/补丁自身三项CRC全部核对，反向应用逐字节恢复原ROM。输出CRC与反馈诊断吻合。UPS有600条非零XOR记录，合计改变22615字节，集中于`0805B9E1..0805B9E8`、`087C8057..087C805B`、`08A7A024..08A7FAE0`（右端不含）。前两处接入新菜单，第三处为新增代码、文本和表。

`ups_patch.py`只在内存解析和应用，默认严格要求正向输入身份，反向必须显式指定；不提供忽略CRC选项。偏移、记录终止及CRC语义参照[Flips一手UPS实现](https://raw.githubusercontent.com/Alcaro/Flips/master/libups.cpp)。ROM、UPS、存档与个人报告均不入库。

## 配置与写入保护

`tools/build_patch_contract.py`先从精确原版复现原契约，再严格应用已审计UPS，使用显式研究入口`extract_for_layout`重提取全部资料。41983次读取生成的配置除真实ROM的SHA/CRC外完全相同。普通`extract()`和其CLI仍拒绝未知ROM，研究入口不授权运行时编辑，也不改变`RELEASES`。

原始读取中一条44字节道具记录包含变化：道具13的场外使用回调指针，位于记录偏移27..30；价格、口袋、持有作用、学习器索引及所有其它已提取数值没有变化。该33000字节元数据段以明确审计例外登记两端摘要，运行时仍严格比较完整目标摘要，未放开任意表变化。

现有90项事务/未知图腾/野生遭遇代码特征均与原版一致。补丁契约保留全部163段原保护几何，按实际补丁内容重算摘要，并新增完整`08A7A000..08A80000`保护区，覆盖未变化的字节、字面量池与间隙。该区开头含24个原有非FF字节，不能将整个区域描述为空闲；真正注入从`08A7A024`开始。

补丁版共164段、9002173字节保护量，显式声明payload连续覆盖范围。原保护段缺失、额外区重叠、声明区有空隙、删除payload guard、元数据例外不匹配均拒绝。普通ROM与所有补丁候选一起判定唯一性；正确CRC不能替代字节核验。

识别后显示“结构兼容 · 内置修改器补丁 · 基线V1.33”。`rom_sha256/layout_sha256`仍指布局，实际文件SHA/在线CRC用于快照、备份、引用与盒锁隔离。每次写入前重新核对补丁后的完整保护范围，包括新增payload；原版备份不能跨身份套用。RTC本地操作仍要求选择实际ROM并核对SHA。野生控制的固定入口、stub和额外守卫与本补丁无冲突；仅归一化当前连接明确拥有的临时覆盖。

## 1.0与1.2的移植边界

这份UPS的输入CRC限定1.33，不能直接对旧版关闭校验套用。三版的两处接入点周边和注入区域原像确实相同，部分调用也经过稳定的原版入口；这使移植研究有依据，但不等于全部依赖兼容。

已找到两个实际引用：`08A7D3B4..08A7D3BC`经过表项调用`09CEBC35`；`08A7D568`开始的函数通过表项访问`097BB0A4`。1.0中前者不在对应函数入口，后者的匹配表基址为`097BB0A0`，直接套用会错位4字节。1.2这两处更接近1.33，但尚未完成整个外部函数、表和脚本依赖闭包，也没有旧版移植菜单的动态验收。因此本轮仅登记1.33补丁版，未声称1.0/1.2补丁移植完成。

后续旧版适配需要逐版重定位这些依赖，验证所有菜单处理函数和保存重载，再生成有正确输入/输出CRC的对应UPS及独立契约。不能通过反推目标CRC或更改白名单替代这些步骤。

## 验证及尚待验收

实际补丁镜像的离线结构识别通过。实际Lua解释器/TCP、真实补丁ROM字节及合成RAM的队伍编辑、读回、条件恢复通过；保持缓存CRC不变再篡改物种数值表，会在写前拒绝。此验证还覆盖允许的标题变化衍生文件，不写用户模拟器、ROM或存档。`tools/verify_builtin_patch.py --lua-tcp`还验证内置补丁与外置野生覆盖的结构复验、启停和条件读回，以及不属于外置覆盖的payload变化仍被拒绝；cart0为合成内存，不证明实际CPU取指。

原反馈的在线首失败块为`080000BE`，严格重建补丁镜像的离线首失败块为`080500BE`；第一块实际未变化，原诊断未保存读取字节摘要，尚不能解释其运行环境差异。新诊断增加应用版本及失败块预期/实际摘要，供反馈用户复测。新包是否解决其具体在线环境，仍以实际使用结果为准。

本轮没有在实际mGBA或手机模拟器打开内置菜单，也未验证同时使用两套修改器、地图战斗及游戏保存重载。子会话《水银内置修改器用途与移动端方案分析》另给出了功能、游玩目标及移动端路线分析；静态菜单文字不等于功能实测。
